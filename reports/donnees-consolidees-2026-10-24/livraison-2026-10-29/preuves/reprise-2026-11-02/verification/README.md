# Reproduction des preuves du2novembre

Ces recettes complètent le suivi existant. Les sources natives ne sont pas recollectées par les rapprochements.

- refresh-matrix-20261102.py BASE CAPTURE OUTPUT : rapproche les déclarations du manifeste public et conserve les identités historiques. Utilise les fichiers listing-slots-current.json du relevé et listing-slots-master-2c8a19d.json des preuves.
- refresh-ledger-20261102.py BASE CAPTURE MATRIX_OUTPUT OUTPUT : conserve toutes les anciennes identités, les661diagnostics et79cas. Une absence ne constitue pas une résolution.
- group-diagnostics-20261102.py SOURCE_EXISTANTE CAPTURE OUTPUT.csv.gz : réutilise la fonction group du suivi1novembre sans lancer sa collecte. Un regroupement n’est pas nécessairement une panne indépendante.
- Les recettes navigateur doivent être copiées sous scripts/ dans un checkout complet du même dépôt, avec Playwright préparé. Les variables requises figurent dans leur source ; elles vérifient les calculs des fichiers effectivement publiés. Aucun résultat isolé ne vaut preuve fournisseur.
- git-ref-loader.mjs et export-listing-slots.mjs lisent les modules à une révisionGit sans changer l’arbre ni les données. Les cotations GLUX/CI5 sont distinguées par l’identité complète.

Les plans et résultats ordinaires sont conservés dans native/, les résultats publics etPNG dans les répertoires public-*. Les reçus de publication doivent correspondre au code, données et empreintes indiqués ; ils ne certifient pas tous les champs du catalogue.
